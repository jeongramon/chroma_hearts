| Path | Contents | Distribution |
|---|---|---|
| `openwebui_knowledge_base/` | Captured baseline, S1 and S2 backend stores | Tracked sample files |

| `experiment_results/` | Recorded recovery, Open WebUI, and mitigation results | Tracked result files |
| `documents_arxiv50/` | The 50 source PDFs | Local; prepare with the script below |
| `experiments/` | Generated workload stores, intermediate references and reports | Local; regenerated by the experiment scripts |

```bash
python scripts/prepare_pdfs.py --download
```

Alternatively use `--source-dir /path/to/pdfs`, or omit both options to verify an
existing local corpus. The original environment produced 1,161 chunks of at most
2,000 characters with 300-character overlap. The manifest verifies both PDF bytes
and extracted chunk text. This is an arXiv PDF corpus, not generated synthetic PDFs;
only the controlled embeddings are synthetic deterministic hashes.

## Open WebUI snapshots

The same 50 PDFs were uploaded to an Open WebUI 0.7.2 knowledge base using Chroma
1.4.0, 1,000-character / 100-overlap chunks, and `all-MiniLM-L6-v2` embeddings.
There are 2,434 knowledge-base chunks. Ten questions were asked before capturing
the deletion scenarios.

| Directory | State | Deleted knowledge-base chunks |
|---|---|---:|
| `baseline_add_only/` | Before deletion | 0 |
| `delete_half/` | S1: half of the documents deleted | 1,241 |
| `delete_all/` | S2: knowledge-base collection dropped | 2,434 |

The historical `baseline_add_only` name denotes the pre-deletion state. Each case
contains `vector_db/` (the Chroma store) and `webui.db` (application metadata).
Original upload PDFs are not tracked in `uploads/`. File-level collections can
remain active after knowledge-base deletion and are excluded from target grading.

```bash
python scripts/run_openwebui_audit.py
```

This builds the before-reference and re-audits both after-states. The parser and
SDK read disposable copies; keep original evidence unchanged. Results identify
known deleted targets only during evaluation, after extraction.

## Results and reproduction

[experiment_results/README.md](experiment_results/README.md) describes the recorded
results and their validation evidence. [scripts/README.md](../scripts/README.md)
gives the execution sequence for the controlled experiment, case study, and
mitigation checks.

Generated stores and PDFs are not bundled as a separate release archive. They can
be prepared/regenerated using the manifest and scripts. Existing local datasets
from earlier experiments are preserved but are not part of the current experiment
workflow. Superseded tracked summaries and drivers can be retrieved from Git
history at `d49fa5f`; they are not current experiment results.
